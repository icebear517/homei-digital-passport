# 數位和美幫：集章與環保加分方案

狀態：2026-09-26 原始討論稿，保留作決策背景。2026-09-28 已依使用者授權實作「店家入口自動啟動好友驗證」與環保加分預覽；最新進度與設定請以根目錄 README.md 為準。以下分數仍是示範規則，不是正式活動辦法。

## 已確認的需求

- 主辦方官方帳號作為活動入口與集章紀錄中心，各店家官方帳號放置同一套 LIFF 的入口。
- 有加入店家 LINE 官方帳號可以獲得該店的章。
- 加入環保杯與騎乘 MOOVO 公共自行車兩種環保加分任務。

## 建議計分規則（待確認）

| 任務 | 建議獎勵 | 建議限制 | 驗證方式 |
| --- | --- | --- | --- |
| 加入店家官方帳號 | 該店 1 枚章 | 每人每店每活動一次；原有好友也可領 | 店家帳號串接驗證；未串接時由店員現場確認 |
| 使用自備環保杯 | 環保分 +1 | 每人全活動各店合計每日一次 | 店員確認當次實際使用，再核發 |
| 騎乘 MOOVO 探店 | 環保分 +1 | 每人全活動各店合計每日一次 | 店員查看本人當日騎乘紀錄，再核發 |

每日以 Asia/Taipei 計算。以上點數與限制為建議值，尚未作為正式規則實作。

店家章與環保分分開顯示及記錄。例：3 枚店家章、2 分環保分；兌換門檻另行設定，不預設環保分可以抵店家章。

## 店家好友章流程

1. 民眾從任一家店的圖文選單進入主辦 LIFF，登入後看到自己的集章冊。
2. 選擇店家，開啟加入該店官方帳號的入口。
3. 驗證已加入且未封鎖該店帳號後，後端發給該店章。
4. 已有好友在活動期間也可驗證領章；重複驗證、封鎖後重新加入皆不重複發章。

點擊加入好友按鈕、打開店家聊天視窗、URL 帶有店家代碼，都不能單獨證明好友狀態。

此方案將「好友章」視為獨立任務，不額外要求消費或到店。若仍要保留實地探店章，必須另列任務並決定是否可同店取得兩種章。

## 自動驗證的串接條件

一般 LIFF 的 getFriendship 只能取得所屬 LINE Login channel 綁定官方帳號的好友狀態。主辦 LIFF 的驗證不能直接拿來判斷全部店家。

可行候選方案：各店家有綁定自己官方帳號的 LINE Login channel，從主辦 LIFF 啟動一次性的店家驗證流程，後端交換及驗證該店 channel 的登入憑證，再以該憑證查詢好友狀態，將結果安全綁回發起驗證的主辦會員。跨 Provider 不可直接以 LINE user ID 相等判斷同一會員，也不可接受前端自行傳回的 friendFlag 作為發章依據。

需要先盤點店家帳號管理權限、Provider、現有 LINE Login channel 及 Messaging API。店家 follow webhook 可協助更新狀態，但不能單靠新 follow 事件涵蓋既有好友；跨 Provider 也需要明確的會員綁定流程。

未具備串接條件的店家，可採店員現場確認好友狀態後核發的方案，並將驗證來源記為人工確認，不宣稱為 API 自動判斷。

LINE MINI App 的多帳號 add-friend 功能，目前官方文件限定服務地區為 Japan，本臺灣活動不以此功能作為前提。

## 環保任務流程

民眾實際使用自備杯，或出示本人當日 MOOVO 騎乘紀錄，由授權店員選擇任務並核發一次性憑證。後端記錄會員、任務、驗證店家、核發時間與使用時間，並在交易內檢查跨店每日上限。

MOOVO 自動串接尚未確認；此階段採現場查看紀錄的建議，不以 GPS 到站、掃固定 QR 或民眾自行勾選當作已騎乘的證明。不預設需要上傳或保存騎乘截圖。

## 現有程式與需求差異

早期草稿是店員產生短效集章碼、民眾掃碼領章，以及民眾產生兌換碼、店員核銷。2026-09-28 已改為好友章自動驗證；店員產生的短效碼只發環保分。兌換仍由民眾出示碼、店員核銷。

原稿當時尚待新增的店家好友驗證、任務類型、環保積分紀錄、跨店每日上限及對應畫面，已於 2026-09-28 加入本機版本。仍未接入正式 LINE 或 MOOVO 帳號，亦未部署。
